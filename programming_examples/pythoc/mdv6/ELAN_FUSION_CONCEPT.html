On-device ELAN fusion — concept sketch

RepNCSPELAN8 block @ 20×20 · keep intermediates resident in memtile L2 · do the GELAN concat on-chip · collapse ~9 launches → 1–2
Scoped 2026-06-21. M0 PROVEN on HW: the on-device channel concat is BIT_EXACT vs np.concatenate (0/32768, max_diff 0.0); concat→conv4 is byte-identical to the host path. Binding constraint = ~29 hw-context ceiling + re4 shim-BDs, NOT L2 capacity.
Reframe (from the PDI-merge study): the concat's real value is as a stitching enabler — removing the host concat/split lets a whole RepNCSPELAN block become one no-host-touch segment, stitchable into one ELF where host dispatches (~505 µs) become on-device PDI swaps (~40 µs). The win is dispatch consolidation, not the bounce.
STATUS (2026-06-21): all primitives proven on HW; rnm→c3 fusion integrated in-model (98→94 launches, 29→28 ctx, 0.1420 PASS) but wall NEUTRAL. Full single-ELF block blocked on a chain→rnm tiles→rows reformat. Dispatch reduction confirmed wall-flat at this scope — see §5.

The block is conv1(1×1) → split(x1,x2) → [RepNCSP+3×3]→x3 → [RepNCSP+3×3]→x4 → concat[x1,x2,x3,x4] → conv4(1×1). Today each sub-op is a separate NPU launch whose output is DMA'd to DDR, re-assembled on the host (the concat / split are np.concatenate), and re-uploaded for the next launch. The fusion keeps all four branch tensors resident in L2 and performs the concat as a strided memtile DMA — the next conv reads a fused tensor directly.

1 · Today vs. fused — the launch & DDR picture

Left: today — 8–9 launches, every intermediate crosses DDR and is reshuffled on the host (red = DDR round-trips). Right: fused — one device holds x1–x4 in L2; the concat is a channel-offset DMA; only the block's input and output touch DDR.

2 · The on-chip concat — a strided DMA, not a memcpy

M0 update: proven on HW, but the IRON construct is a single strided gather rt.fill, not 4 offset-only DMAs — a fill's dest is linear, so the interleave lives in the source strides (sources passed stacked [x1|x2|x3|x4], gathered per-pixel: sizes=[tile_m,4,128], strides=[128, host_q, 1]). Mathematically identical to the scatter; bit-exact. (The symmetric drain does take a dest-scatter TAP, as the rn3 chain uses.)

But capacity is NOT what binds. The scope confirmed the working set fits at 20² (and even re6/re4 fit in total L2). The actual binding constraints are: (1) the ~29 hw-context ceiling — the model already uses exactly 29, so a fused-block ELF must be context-neutral by evicting the chain/conv contexts it subsumes; (2) re4's shim-BD pool (16/ch) — TPC=12 already overflows it (the same 24>16 wall that disables re4's rnm-fold). re8 clears both; re6 is harder; re4 likely needs BD relief first.

5 · Milestone ladder & measured outcome

  • Milestone 0 — standalone concat proof: DONE ✓ (2026-06-21) on-device strided concat → conv4 GEMM. concat_only BIT_EXACT vs np.concatenate (0/32768, max_diff 0.0, incl. the quarter-boundary seam); e2e concat→conv4 byte-identical to the host-concat→GEMM path.   • Producer→consumer stitch DONE ✓ — build_merged chain_links=[(prod_out,cons_in)]: device-resident intermediate, 1 ELF / 1 hw_context, bit-exact. Measured PDI-swap floor ~39 µs vs ~505 µs host dispatch. A merged ELF = 1 context regardless of sub-device count (B2a: 2 GEMMs → ctx 2→1).
  • chain as 1-context xrt.elf DONE ✓ — the rn3 chain migrated off ResidentXCLBinRunner into a merged ELF, bit-exact.
  • KEYSTONE — halo-gather 3×3 from padded-HWC DONE ✓ — a 3×3 conv reads halo'd windows directly from a padded image via an overlapping-window rt.fill TAP (overlap is only forbidden for split). Eliminates the 4.08× im2col blowup that blocked conv0→conv1, chain→c3 and full-block fusion. OC=128 fits L1 via per-oc-block C-drain.
  • rnm→c3 device-resident seam DONE ✓ — the real 128→128 model seam (rnm 1×1 drains PAD-padded HWC → halo_c3 reads it), 1 ELF / 1 ctx, bit-exact 0.037.
  • In-model integration DONE ✓ — rnm→c3 fused across all 4 re8 hops behind MDV6_FUSE_RE8: launches 98→94, hw_context 29→28, accuracy 0.1420 PASS, wall neutral.
  • Full single-ELF block BLOCKED — gated on a chain→rnm tiles→rows reformat (chain drains 8×8 tiles; rnm wants per-core rows + x2-interleave — no single TAP bridges them) and the chain's separate runtime context.

Measured outcome (2026-06-21): every primitive is HW-proven and the rnm→c3 fusion is integrated in the live model bit-exact — but at re8 scale the wall is neutral (−4 launches is below noise; launch_gap is already at its floor, and the concat/stitch remove plumbing, not compute). This re-confirms the session's recurring finding: dispatch/context reduction does not move this wall at achievable scope (packed-GEMM −9 = flat; rnm-fold regressed; re8 fusion −4 = flat). The model-wide ~40 ms target would need re6/re4 fusion + the chain→rnm reformat + BN/SiLU-in-kernel + displacing tail ELFs — a multi-week rollout whose payoff is still bounded by dispatch-floor economics. Hard bound: the heavy c3 kernel compute stays; making the convs themselves faster (BFP576/wider matmul) is the complementary, larger lever. The fusion work is banked as a de-risked, gated primitive library (all seams proven), ready for that rollout if/when funded.
